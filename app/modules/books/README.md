未完成 / 需要的共享改动：

- 完整企业科目表仍未完成：原分析只确认a01/a02名称和级次，未确认修订版本；[财政部答复](https://www.mof.gov.cn/bd/mhwzzxly/hjs/202301/t20230104_3861971.htm)区分2006附录和2014年以来指南，不能混拼。现有2019附件是报表格式；[2006官方通知](https://czj.sh.gov.cn/zys_8908/zcfg_8983/zcfb_8985/hj_9035/cwhjjbzdgf/20061201/0017-156907.html)可读，但其RAR附件在本环境返回403，上海税务旧入口404，尚缺完整可核读原表。旧9项JSON、ID及全部 `needsReview:true` 保留，未注册虚构完整版或将2026征求意见稿当生效规则。
- [商务部转载线索](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=13655)不作正式底稿：表中67/68项编号有内部空格，2002表名“存入保险金”与处理标题“存入保证金”冲突，且有采集限制。未据其生成或登记模板，亦未凭记忆修正。最小缺口仍是允许读取的2006正式完整原表及逐项主要账务处理，足以核清这些冲突和方向；不以2014后修订、2019报表或2026征求稿代替。
- `enterprise-evidence.ts` 只核对来源声明和结构一致性，不能证明原稿权威性、转录正确或采集许可。校验同版本、来源摘要、原表行数/顺序、唯一四位一级编号、名称/类别与方向定位、行业范围和科目性质。双向、无期末余额及未知性质均强制 `needsReview`：当前core借/贷值只是显示占位，不代表完整业务语义支持。真实SQLite回归保留旧账套重开不补改、凭证/余额/日志不变及整数取数；中途失败清理锁定 `account_dimension` 唯一约束。当前仍只有合成夹具，没有完整官方表验收结论。
- 单一共享契约需求：科目语义元数据（来源、待核状态、双向/无期末余额等性质）须随模板建账事务持久化，并由科目API完整返回；当前core仅存借/贷方向且丢弃这些字段。本模块不改共享层、不把占位当作支持完成。
- 小企业为 `small-appendix.pdf` 第1—3页66项原表快照，5403保留“营业税金及附加”；后续更名、专项增补及法定报表尚未覆盖。1702第33—34页第三项贷记与第四项“借方余额”矛盾，按备抵贷方设置并标记待核勘误。
- 其它本位币需共享 `CreateBookInput` / `BookStore.create` 扩展；空白/用户自定义制度受至少一个科目的schema限制，未提供假选项。
- 通用恢复/备份管理归M18，账册与打印设置归M19，科目编码调整归M03，业务设置归M05/M07。未建立这些模块的假链接；首次建账以外的破坏性重新初始化不在本模块实现。
- W0 `TabsHost` 需稳定标题回调并避免无变化时反复生成标签数组；修复后可删除本模块整页菜单导航兼容钩子。跨模块统一跳转仍需共享壳集成。
- 实际删除未实现并已在服务端阻止：最终快照不能覆盖之后的写入，在线移动主文件可能遗漏WAL中的晚提交。现有安全core已有目录/请求租约、排空及reconnect，仍明确拒绝delete/replace，不能排除未知外部SQLite连接。执行删除仍需安全核心明确支持跨模块/跨进程的破坏性维护契约：阻止新认证/打开/迁移/读写，排空并关闭全部连接，消除close期间重新打开窗口，再设计可恢复文件交换、强确认及会话失效。本模块不自行接管这些前提，不执行移出、永久删除或崩溃恢复；模块互斥锁与已有备份不能替代它们。
- core公共创建接口没有幂等键：本模块阻止同窗口重复点击，但网络响应丢失后的跨请求建账幂等需要共享支持，不能宣称已实现。
- Windows/Electron及旧原版SQL Anywhere资料导入尚未验证；本次使用合成账套，不以单测/E2E数量代替功能完成。
