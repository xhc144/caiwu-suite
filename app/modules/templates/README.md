# 会计制度科目模板

在“新建账套”的行业选择中提供下列制度、科目和明细，对照原版 `w_xt_kgzb_a2`、`w_xt_kgzb_a3`、`w_xt_kgzb_1/3`。模板只用于新账，升级和重新打开已有账套不自动改动其科目或辅助配置。另提供建账前适用性查询及强制复检的创建接口，创建仍委托既有建账事务和科目级次映射。

明细名称和分类按原文，原文规定数字编码的保留原编码；未规定数字的采用应用默认后缀，逐项 `source` 明确标注。默认借贷方向不限制实际双向余额，备抵、无期末余额及特定结转用途独立保存。没有预造实际成员、单位、人员、项目、银行账户或资产。正式记账必须选末级，并补齐该末级要求的真实辅助对象。

民非、农合及农村集体分别适用2026、2023、2024年施行版本，两类工会适用2022年施行版本。民非增值税默认小规模纳税人，未强制给所有组织建立一般纳税人专栏。个体保留制度原有“营业税金”等名称，不预设旧税率、不自动计算应税所得。安徽食堂仅适用于模板注明的地区、学校及营养计划，不是全国学校/幼儿园食堂通用制度。

## 未完成与共享接回

- 尚未预设按实际业务增设的资产类别/品名、资本公积来源、盈余公积用途、年度亏损及完整税种；一般纳税人增值税专栏须按纳税人身份配置。成员与非成员需正确建档，现有通用往来档案不能强制筛选成员属性。工会未内置逐年度预算经济分类、支出功能分类目录。
- 本模块不包含自动结转、成员权益备查簿、民非首次执行转换、限定性捐赠管理或法定报表，`reports: []`。原自定义99空表、覆盖已有数据的系统初始化及工资/资产/成本专门初始化未在本模块实现。
- 原44项逐一对应 `legacy-catalog.ts`，服务端 `originalCatalog` 同时返回实际已登记的模板ID。现行覆盖16项、居民医保现行替代1项、安徽学校食堂地区覆盖1项、地方党费参考1项、需双体系5项、缺原始来源4项、缺历史版本16项；替代与地区参考不计为原档案恢复。a23出纳、a24广东残联、a42民办幼儿园及a51幼儿园食堂仍须原始适用文件。历史基建和政府基建子集不注册，企业及小企业基表保持原样。
- 政府2019与财政总会计2023均要求财务、预算两套核算分别平衡。需共享科目增加 `ledgerSystem`，凭证按体系分别校验并关联同一业务的两组分录，余额/试算/结转可按体系查询后，才能提供完整现行模板。[政府制度](https://kjs.mof.gov.cn/zhengcefabu/201711/P020250721410368429134.pdf)总说明第五/六项、[财政总会计制度](https://gks.mof.gov.cn/guizhangzhidu/202212/P020221221366063217022.pdf)第七/十四条为依据。
- 典当与融资担保采用企业准则，行业派生在本模块通过既有启动钩子读取已登记企业基表，再转换并登记普通模板；无需新增共享接口或复制248科目。典当依据[财会〔2009〕11号](https://kjs.mof.gov.cn/zhengcefabu/200907/t20090728_188187.htm)，已在行业方案中补1409绝当物品；融资担保依据[解释4第八问](https://www.mofcom.gov.cn/zcfb/zgdwjjmywg/art/2010/art_5bb942ee69264505a85258e081388a5a.html)，不恢复已停止执行的旧担保办法。未取得全国统一党费独立科目表，不编造“党费2017”制度。
- `core.books.create`、模板创建接口与主运行时建账共用写文件前校验，复检当前年月、地区适用范围和担保合同事实；拒绝不留下账套或占用请求编号。向导与壳的简易建账框显示条件，切换制度清空旧事实，提交不沿用前次预检结果。合同选择由会计人员确认，当前不记录逐合同不可撤销选择的历史，也不支持同一预设混合两种合同口径。

## 验证与试用

单测按独立原文表核对一级与明细，使用合成SQLite账套验证级次映射、父链、末级记账、缺对象/权限/期间拒绝、事务失败无残留、保存重试、持久化及旧账隔离；整数分性质测试核对成员往来余额。浏览器测试覆盖全部模板的HTTP建账和登录隔离，以及民非两种级次、工会四层、个体和安徽食堂的真实向导。

新建账套→选择适用制度→确认默认级次（工会县级以上为四层）→创建并登录→按科目说明建立真实辅助档案→选择末级录入凭证。个体税后费用及食堂月末/年末可按制度手动结转；模板不自动代做这些业务。

## 新增制度接入

独立作者只写 `supplements/<行业>/`，不改注册表。完整独立制度直接导出 `templates: readonly unknown[]`（可直接放入 JSON 导入值，注册前严格按会计制度 schema 校验）；企业制度上的行业增量导出 `presets: TemplatePresetInput[]`。可统一导出 `supplement: TemplateSupplement = { templates, presets }`。类型从本模块 `preset.ts` 引用；集成负责人在 `server/supplement-catalog.ts` 显式接入，不能跨模块导入企业数据。

行业方案字段为 `id/version/name/description/order/baseTemplateId/baseTemplateVersion/sources`，可选 `additionalAccounts/accountOverrides/additionalCategories/codeScheme`。新增科目提供完整定义和来源；覆盖仅改已存在编码并必须提供修改依据。典当等可基于 `books-enterprise-cas-2006@2006.18+2026.2` 增补行业科目；未改变的基表来源版本保持，覆盖和新增另存行业版本。

启动时在全部静态基表登记后解析方案；重复编码、重复类别、版本不符、循环依赖、无来源修改或缺失父级会拒绝，整批解析成功后才登记。实际建账继续使用共享建账事务和级次映射。双体系政府/财政不能借此转换为一套余额表；未知的体系字段会被拒绝。

## 行业补充接入

已接入建筑施工两套、典当、企业基建、房地产、融资担保两口径及小贷八个行业方案，均复用已注册企业/小企业基表；地方党费保持济宁港航参考口径及deprecated状态，不进入现行制度向导默认选项。历史基建1996/1998定义和政府基建子集仍不登记。

担保两口径分别保留，不按企业名称或年份默认选择。金融工具方案须明确确认财务担保合同及未作公允价值指定；保险合同方案另外要求之前明确视作保险合同、已按保险合同核算及单项合同不可撤销选择。[财政部实施问答](https://kjs.mof.gov.cn/zt/kjzzss/sswd/jrgjzzss/202103/t20210302_3664216.htm)为依据。原企业/小企业仍是向导首选。

## 建账宿主最小接线

- 只读 `m.templates.creationPolicies` 返回结构化起始日/范围；`m.templates.checkCreation({templateId,startYear,startMonth,facts})` 返回 `allowed/issues/policy`。年份、月份或所选制度变化后必须重查，不能沿用旧的通过结果。
- 提交可用 `core.books.create({...原CreateBookInput,facts})` 或 `m.templates.createBook`；服务端在写文件前重新校验，保留原请求编号的并发/重启重试语义，事实字段顺序变化不改变同一请求。两个接口都在登录前调用；不增加已存在账套的写权限。
- `web/TemplateCreationFields.tsx` 可复用日期说明、担保单选与逐项条件；受控参数为 `templateId/startYear/startMonth/value/onChange`。`shared.ts` 定义事实类型。切换制度应清空相关事实，提交时传当前值；不预先勾选任何口径或确认项。
- 静态模板通过 `validateBookCreation`、行业方案通过 `TemplateRegistry.register` 同时登记 `assertTemplateCreation`。主运行时将校验传入 `BookStore.create`；内部受管初始化暂存库不注册用户新建策略，打开和复制旧账也不经过新建校验。前端宿主注入模板字段与校验，books 不跨模块引用。不能在建账后钩子里抛错或删除新账代替事前拒绝。另需逐合同选择及不可撤销历史存储后，才可声称跨年度维持合同选择。
- 政府/财政共享需求：模板和科目的 `ledgerSystem: financial|budget`；分录所属体系及同业务关联标识；同一事务分别验证财务、预算借贷平衡；余额、试算、期初和结转接受体系筛选，并持久化体系来源。财务账与预算账必须能在同一账套配对，不能注册两个普通单体系模板冒充。
