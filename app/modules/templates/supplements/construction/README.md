# 建筑施工科目补充

对应原版 `w_xt_kgzb_a2` 行业选择的 a07 建筑施工与 a08 旧建筑施工、`w_xt_kgzb_a3` 科目级次，以及 `w_xt_kgzb_3` 新建账套科目分支。原版静态清单见 `docs/original-analysis/data/tables.md`；本目录不读取安装包或真实账套，不把科目数据定义算成完整用户功能。

| 预设 | 基表及版本 | 提供内容 |
| --- | --- | --- |
| `construction-cas-revenue-2017` | `books-enterprise-cas-2006@2006.18+2026.2` | 继承企业基表248项，追加1490合同结算及价款结算、收入结转；合同成本/资产/负债按合同使用项目辅助，停用5401/5402旧模型，新建账共251项 |
| `construction-small-business-2013` | `books-small-business@2011.17+2016.22` | 继承66项，追加1411在库/在用/摊销及4401合同成本/间接费用，4403标记期末结清；共71项，不混用企业准则合同结算/合同毛利 |
| `construction-enterprise-system-2003` | 尚缺完整2001企业会计制度基表 | 已录7项增设一级及规定明细、1281合同预计损失准备等；仅供核对，合成函数明确拒绝注册，不能作为完整旧账套 |

`index.ts` 的生产接入口是 `supplement: TemplateSupplement`，定义位于 `supplement.ts`，仅从 `../../preset` import type，输出两套差量 `presets`，无完整基表副本、无 `templates`。由统一owner在 `server/supplement-catalog.ts` 登记一次；基础制度来自既有registry。省略的dimensions字段保持省略，不转换成清空。2003包不在可注册列表。

独立builder保留供测试和核对：`materializeConstructionTemplate(base: unknown, id: ConstructionPresetId, options?: {codeScheme?: string; startDate?: string}): AccountingTemplate` 与 `buildConstructionTemplates(bases: readonly unknown[]): AccountingTemplate[]`。纯合成，不import其他模块、不改registry。父级沿用基表编码、类别和方向；增设编号占用、父链缺失、基表版本/方向不合均拒绝。先在原生4-2-2下合成，再由core逐段映射4-3-3，149001变1490001、440101变4401001。不能直接改变字符串长度或补零到末尾。

企业版1490及所有新增明细编号是软件分配，法定名称和核算内容来自原文，并非财政部统一编号。1490按资产类别收纳是软件分组；期末须按同一合同净额借贷方向及流动性分别列报，不得跨合同抵销。项目档案须一项代表一份合同，由用户建立，不预造合同、客户、部门或设备。现行版保留独立合同资产/合同负债供其他符合准则业务使用；同一业务选择相应核算方式，不能重复确认。小企业440101合同成本与440102间接费用都按原文4401第二项保留合同项目；跨合同间接费用分配业务由成本模块处理，不能伪造一个“公共合同”档案代替。

原文出处集中在 `sources.ts`，每项数据另有条款定位。当前企业模型依据财会〔2017〕22号、财会〔2019〕6号附件2第22—24项；后者的科目说明用于核对合同结算及合同成本，不据此宣称已完成2026报表。小企业依据仓库 `small-standard.pdf`、`small-appendix.pdf` 的1411与4401/4403；未将2017收入准则强加给小企业。2003办法在2004-01-01起适用于执行《企业会计制度》的施工企业，不能与2006企业会计准则基表合并。2015废止通知针对1992制度，不是2003办法。原始清单没有给a07/a08标具体发文字号，因此本目录不宣称逐行恢复原安装模板。

独立测试入口：在 `app` 运行 `node modules/templates/supplements/construction/test/run.mjs`。只读基表快照位于 `test/fixtures/`，用于独立复现，不注册、也不在生产中读取。快照来自当前books静态定义及chart的字段映射，保留基表版本、原始依据、备抵及余额性质。测试覆盖两级次真实SQLite建账、末级制证、项目辅助拒绝、整数分借贷不平、期初、合同成本/收入/结算/收款、分合同余额、事务回滚和随机整数分汇总。类型检查入口为 `tsconfig.check.json`。

## 未完成

- 统一registry及真实建账向导由集成owner接入；本目录不改server/registry/books/core。启用日期如由向导传入builder会校验；统一preset契约不提供生效日期/适用资格字段，不能声称所有建账调用已执行该校验。基表`reports:[]`，本补充不赋予报表能力。
- 小企业基表1702累计摊销的原文余额方向与计提分录矛盾，按基表保留贷方处理与`needsReview:true`，不悄悄解除待核标记。
- 2001制度完整财政/监管原文科目表、1992施工制度完整科目表尚未获得。常州2003转载将主营业务成本号印作5102，与通常基表5401存在冲突；历史包中5401的父级定位仍须基表原文独立核定，不据转载错误生成正式模板。
- 未提供设施/周转材料种类、机械设备、成本对象的实际企业明细，不虚构档案；2003办法允许按需增设的拨付所属资金、上级拨入资金、内部往来未擅自分配编号。历史数据不能充当1992制度完整恢复或当前默认。
- 不提供履约义务识别、成本分配业务、自动收入确认、增值税计算、法定报表、首次执行转换及已有账套迁移。现有core的期初写入没有统一执行所有科目辅助必填检查；测试以合法带辅助期初核对余额，不能声称缺辅助期初已被向导拒绝。
