# W2-22 标准化账务导入

这是新空账的 Excel/文本导入，不是原版 `.bak` 兼容或完整账套迁移。

| 原版入口 / 规则 | 当前覆盖 |
|---|---|
| `w_xt_kmbm_get` 导入科目：文件、空数据、编码级次、上级存在 | 已实现：四表预检、列映射、科目新增或与模板逐字段比对；冲突阻止，不覆盖模板。 |
| `w_pz_get` / `_bak` / `_bb`：文件、空数据、编号不超过 10000、日期、已审核记账、已有编号、无效科目 | 已实现：仅待审核、启用年度内凭证，保留原编号、附单数、行序与摘要；同号、无效或非末级科目、任何错误均整批阻止，不替换科目、不带错转入。原版时钟版许可证截止规则有意不移植，新程序没有此许可证机制。 |
| `w_xt_ye` / `w_xt_ye_nf`：期初年份、借贷平衡 | 已实现：仅 1 月启用；来源末级科目必须含全量期初和余额（含零），年初累计必须为零；逐科目核对期初、发生、期末及累计。 |
| `w_bb_saveas` 导出后的文件导入 | 本次实现：一个四表 `.xlsx` 或四个 CSV/TSV/TXT，UTF-8 / 明确选择 GB18030；必须先规范化为本模块字段。未声称直接识别原版任意导出格式。 |
| 来源与重复保护、全量回滚 | 本次实现：文件 SHA-256、规范化内容哈希、预检人/30 分钟有效期/目标快照绑定、同账一次导入；真实 core 事务预演后回滚，提交回读科目/期初/凭证/余额/计数，晚期失败整批回滚；来源可回查。修改、删除、作废走 core 来源锁。 |
| 新账与原数据保护 | 本次实现：仅 24 小时内新建的空账，所有业务表及未知表有行从严阻止；仅认可当前基线的模块默认初始化行。已有凭证、期初、模块设置、保护备份记录或关闭期间均阻止；不打开、执行、修改原数据库，不覆盖任何账套。 |

文件合计最多 256 KiB，Excel 解压声明最多 4 MiB；科目/期初/余额各最多 1000 行、凭证最多 500 张/5000 行。Excel 所有单元格必须为文本，不接受数值、日期对象、公式、链接、合并单元格、未知工作表。金额为最多两位小数的十进制元文本，严格转整数分，拒绝舍入、科学计数和超范围合计。可下载完全虚构的示例 Excel。四表与逐字段含义见页面，所有未映射列（即使为空）都阻止。科目类别填目标类别 ID，方向填借/贷，标志填是/否，余额借正贷负。导入人为本次制单人，来源必须已经是无需历史操作员迁移的待审核数据。对照余额包含本次待审核凭证；正式过账余额不计本次凭证发生额。

调查依据：`docs/original-analysis/data/tables.md` 记录 SQL Anywhere 8/9、`kmbm` 7 种、`nc` 2 种、`pz` 6 种、`pzdj` 3 种结构变体；金额原字段多为 double，不能据 DDL 推定实际精度。现有安装资源说明 `tools/original-analysis/README.md` 只提供静态解包/结构文档流程，并无本模块可用的数据库读取器。未下载、重解安装包或运行其程序/DLL；环境没有 dbunload/ODBC 工具，也没有获本次授权的原库样本。[SAP 官方 dbunload 说明](https://help.sap.com/docs/SAP_SQL_Anywhere/61ecb3d4d8be4baaa07cc4db0ddb5d0a/813e16456ce21014b96dc39365129dc6.html)说明旧库版本及恢复存在限制；没有据此安装或运行专有工具。
