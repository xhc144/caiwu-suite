# W2-22 标准化账务导入

标准化入口是新空账的 Excel/文本导入。新增「原生凭证结构预检」只读入口；两者均不代表原版 `.bak` 兼容或完整账套迁移。

| 原版入口 / 规则 | 当前覆盖 |
|---|---|
| `w_xt_kmbm_get` 导入科目：文件、空数据、编码级次、上级存在 | 已实现：四表预检、列映射、科目新增或与模板逐字段比对；冲突阻止，不覆盖模板。 |
| `w_pz_get` / `_bak` / `_bb`：文件、空数据、编号不超过 10000、日期、已审核记账、已有编号、无效科目 | 已实现：仅待审核、启用年度内凭证，保留原编号、附单数、行序与摘要；同号、无效或非末级科目、任何错误均整批阻止，不替换科目、不带错转入。原版时钟版许可证截止规则有意不移植，新程序没有此许可证机制。 |
| `w_xt_ye` / `w_xt_ye_nf`：期初年份、借贷平衡 | 已实现：仅 1 月启用；来源末级科目必须含全量期初和余额（含零），年初累计必须为零；逐科目核对期初、发生、期末及累计。 |
| `w_bb_saveas` 导出后的文件导入 | 本次实现：一个四表 `.xlsx` 或四个 CSV/TSV/TXT，UTF-8 / 明确选择 GB18030；必须先规范化为本模块字段。未声称直接识别原版任意导出格式。 |
| `qingsong/dw_pz_saveas` / `dw_pz_saveas0` 原字段导出 | 新增只读预检：固定字段 profile（33 / 28 列），或同一 saveas 的 `pz`（25 列）/`pzdj`（12 列）显式投影；独立 `pzlx` 三列字典依据 `dw_xt_pzlx`。四键 `nf+yf+pzlx+pzbh` 连接，重复/孤立头行、连续原行序、日期与类型字典检查。saveas0 缺状态及凭证/审核/过账日期，明确阻断，不能补未审核。 |
| 来源与重复保护、全量回滚 | 本次实现：文件 SHA-256、规范化内容哈希、预检人/30 分钟有效期/目标快照绑定、同账一次导入；真实 core 事务预演后回滚，提交回读科目/期初/凭证/余额/计数，晚期失败整批回滚；来源可回查。历史批次切换清空预检提交资格及确认文字；提交时所选批次、地址栏和本次预检必须为同一批，确认卡显示来源与金额。修改、删除、作废和编号调整走 core 来源锁；编号保护由唯一共享 owner 的固定提交 `a8eb1c0b12e2f9931ae2da3f135f6ceee0bcc826` 提供，原拒绝及编号不变断言保留。 |
| 新账与原数据保护 | 本次实现：仅 24 小时内新建的空账，所有业务表及未知表有行从严阻止；仅认可当前基线的模块默认初始化行。已有凭证、期初、模块设置、保护备份记录或关闭期间均阻止；不打开、执行、修改原数据库，不覆盖任何账套。 |

文件合计最多 256 KiB，Excel 解压声明最多 4 MiB；科目/期初/余额各最多 1000 行、凭证最多 500 张/5000 行。Excel 所有单元格必须为文本，不接受数值、日期对象、公式、链接、合并单元格、未知工作表。金额为最多两位小数的十进制元文本，严格转整数分，拒绝舍入、科学计数和超范围合计。可下载完全虚构的示例 Excel。四表与逐字段含义见页面，所有未映射列（即使为空）都阻止。科目类别填目标类别 ID，方向填借/贷，全部五个标志列必须显式映射并填是/否，缺列或空白均阻止，余额借正贷负。导入人为本次制单人，来源必须已经是无需历史操作员迁移的待审核数据。对照余额包含本次待审核凭证；正式过账余额不计本次凭证发生额。

调查依据：`docs/original-analysis/data/tables.md` 记录 SQL Anywhere 8/9、`kmbm` 7 种、`nc` 2 种、`pz` 6 种、`pzdj` 3 种结构变体；金额原字段多为 double，不能据 DDL 推定实际精度。现有安装资源说明 `tools/original-analysis/README.md` 只提供静态解包/结构文档流程，并无本模块可用的数据库读取器。未下载、重解安装包或运行其程序/DLL；静态清单虽含 dbunload.exe / ODBC8/9，但只作线索，不证明许可或实际安装；本任务不取得、不运行原二进制，也没有获本次授权的原库样本。[SAP 官方 dbunload 说明](https://help.sap.com/docs/SAP_SQL_Anywhere/61ecb3d4d8be4baaa07cc4db0ddb5d0a/813e16456ce21014b96dc39365129dc6.html)说明旧库版本及恢复存在限制；没有据此安装或运行专有工具。

原生预检入口 `/m/legacy-import/native` 接受已明确解码的 UTF-8 JSON 文本/文件（`caiwu-native-rows-v1`；可填入纯虚构示例）。`source` 明示 `decoding`、`amountUnit`（`yuan`/`fen`/`unknown`）、`amountEncoding` 和 `currency`；`tables` 每张表含 `name/columns/rows`，格值仅字符串或 null。表名 `pz/pzdj/pzlx` 在此指指定 DW 的投影，不是完整物理表或某个已确认版本的 DDL；拒绝混入 `kmbm/nc`、未知列和其他 profile。四个展示模板交集为空，不能据展示结构拼装真实账套版本。

原生报告保留提交文本 SHA-256、字节数、表内 1 起数据行号、完整原表数组/原值与逐字段覆盖清单；元/分必须明确，BigInt 精确转分，科学计数、超两位元小数、舍入、浮点 JSON、超安全整数分和超限合计均阻断。仅证明收到的文本，不证明原 double 或单位来源保真。原规则只证实状态 1/2 禁止转入，全部历史状态/人员、辅助/外币/数量/单价/结算/票号/结转等有值（含零）阻断，不默认未审核、不丢列；原始字节编码及 PB 转义未知时明确不兼容。缺/未知状态均阻断。所有原生报告明确「原生数据尚未完成迁移；所有目标账务零变化」，纯分析函数不接收账务服务、不建批次、不输出正式执行计划。页面可预检并下载完整报告，没有写账按钮。

物理 SQL Anywhere 读取及全账迁移仍缺：授权原库及配对日志/备份、确切引擎补丁/加密访问条件、合法匹配读取器和恢复环境；原 SaveAs 格式编号、编码/BOM、分隔/引号/NULL/日期/转义规范及成对字节样本；double 与十进制逐笔对照、货币单位证明及精度规则；`pzdj_bz` 全部状态语义、`pzdj_zdr/shr/jzr` 历史人员关联及 `pzdj_rq/shrq/jzrq` NULL/时序规则；同一真实版本完整 DDL/键约束、科目/辅助期初/期间结账/累计/业务表与期末试算对照。精确阻断清单也在页面及下载报告中。
