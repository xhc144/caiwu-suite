接口在 `server/costing.ts`，类型在 `costing-contract.ts`；costing禁止私写inventory表。共享owner须保留当前账套、actor和moduleId，在 `svc.tx(async t => withInventoryCosting(t, async inventory => { ... }))` 中注册/调用适配器。`withInventoryCosting`退出后能力立即失效，旧能力在另一事务中也拒绝；读取可用 `inventoryCosting(svc).snapshot(period)`。不要跨请求缓存适配器。

- `snapshot(period)`：version=1基础字段、actorId/moduleId、fingerprint、stockRevision/openingRevision、正式批次、previousBatchId、用途关联及有sourceBatchId的periodOpening。前月尚未正式核算时periodOpeningReady=false，不编造目标月期初。指纹绑定账套/actor/module及完整来源；inventory页面快照不可直接拿给costing身份发布，需由其绑定服务重新取得。
- `commitCosting({bookId,period,requestKey,expectedStockRevision,expectedOpeningRevision,previousBatchId,fingerprint,lines,balances,countAdjustments})`：lines为`{lineId,documentId,costCents,unitCost}`，balances为`{warehouseId,productId,quantity,amountCents}`；countAdjustments为`{warehouseId,productId,countId,quantity,amountCents,zeroQuantityAdjustmentCents}`。数量字符串、金额整数分；完整集合、月末加权整分分配、守恒、盘点版本和连续月份均验证。返回`{batchId,revision,period,status:'calculated'}`，同requestKey相同actor/内容幂等。
- `cancelCosting({bookId,batchId,expectedRevision})`：仅末正式批次；关联凭证已审核/过账则拒绝，待审核成本凭证经所属module的core服务原子删除，收入/入库用途关联保留。恢复前一控制点、期初/头行/盘点状态与快照金额，撤销调整移动，版本只增加，批次历史不删除。
- `lockVoucherSource({bookId,documentId,purpose,expectedRevision,voucherId})`：purpose为receipt/revenue/cost；先在同一回调用`t.vouchers.create({source:{type:purpose,id:String(documentId)},...})`，再关联。来源module须等于当前绑定module，凭证须为同月未审核正式凭证，金额匹配；用途唯一，同单收入/成本可共存。
- `releaseVoucherSource(同上)`：同一回调内由本方法删除用途关联并调用`t.vouchers.delete`，失败恢复全部；调用方不要先删凭证或再次删除。`expectedRevision`是当前单据revision，关联/释放都会递增。

共享需求：core唯一owner注册上述模块适配器并在每个事务作用域内重新绑定，W2-01使用其本模块权限`costing.view/calculate/voucher`；库存直接接口使用`inventory.view/costing/voucher`。需给costing manifest登记receipt/revenue/cost来源路径。库存已提供`m.inventory.costingSnapshot/commitCosting/cancelCosting`实际入口并以真实账套验证，正式成本与凭证业务页面仍待W2-01接回，未声称跨模块联调完成。`0002/0003`仅追加迁移，保留旧迁移原文；旧盘点金额为null，正式发布后从真实成本补账面金额，撤销恢复原快照。
数量API为十进制字符串，库内`_e6`为整数；金额`_cents`为整数分。单据Excel统一列“产品编号、数量、单价（元）、含税口径（是/否）、说明”，含税口径必填，未知/重复列及空错值拒绝，回导保留原价与口径。默认出库成本/单位成本为null、状态uncalculated。月末加权之外的FIFO目标仍从PR70保留，是否开放需成本owner与根确认，不能据旧README把FIFO当原版已证实方法。
