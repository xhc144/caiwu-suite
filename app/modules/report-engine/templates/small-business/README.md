# 小企业三表（W2-03）

依据 `rules/sources/official/small-appendix.pdf` 第68—85页及编制说明，保留原文项目名。本目录仍是未完成的取数切片，不是完整法定报表。原版入口：`w_bb_main` 报表管理、`w_bb_get` 引入、`w_bb_def` 定义、`w_bb_proc` 生成、`w_bb_saveas` 导出。未读取旧C#或重新解析安装资源。

功能清单：

- `301.json`（code301）：53项行次，32项接真实取数；原30项加存货、在产品两项。应收、应付先按末级科目及往来对象分借贷再汇总，贷方筛选返回正数；期末和年初分别计算。预付借余、预收贷余因缺期限分析仍留缺项。简单项目年初用期末减本年借方累计加本年贷方累计；方向重分类、存货及其四个其中项年初取 `yearStart` 的真实期初，要求存在年度期初期间。
- `inventory-balance.ts` 按附表第70页列明的十项组成映射材料采购、在途物资、原材料、材料成本差异、生产成本、库存商品、商品进销差价、委托加工物资、周转材料、消耗性生物资产。全部使用总账借正贷负余额，两项差异直接相加，不再扣减或取绝对值；在产品读4001实际末级明细，父级不重复计入。补充十项组成相等及剔除有符号差异后的四个其中项包含关系审核，只读总账，不计算或写库存成本、不读库存私有批次。
- 默认301强制引用十项标准母科目，缺任一项由真实BALANCE报错，不漏项默认零；正常新增母科目或其明细后，母科目范围按真实总账动态取数。显式 `extendedBalanceSheetTemplate({ mapping, accounts, period })` 可提供完整母科目范围、完整末级清单或有依据的absent声明。公共profile生成事务重新读取含停用项的完整科目表并调用`validateInventoryMapping`，拒绝角色缺失、absent已出现科目、漏新末级、父子重叠及错母科目。absent的零只在真实不存在经同事务复核后有效；默认母科目继续动态包含合法新叶子，导出核对本次真实来源/科目指纹。非标准科目及附表“等”所指的其它存货还需真实分类依据，不能据十项映射宣称任意账套已完整覆盖。
- `302-monthly.json` / `302-annual.json`（code302）：32项行次，默认13个主项/合计接真实结转前净发生额。月报本年累计/本月，年报本年累计/上年全年；上年固定 `previousYearStart` 至 `previousYearEnd`，不使用上年同月。只排 `closing_kind='pnl'`，保留其它结转、退货、冲减、投资损失及利息收入。原文3项利润合计审核已接通。
- `extendedIncomeTemplate(mode, details)` 可按明确的真实明细科目映射填齐32行及6组“其中项”包含关系审核；映射必须属于对应母科目且不能重复或上下级重叠。默认JSON没有猜测19个明细项目的二级编码，它们仍显示“未实现”。明细映射的用户配置入口尚未实现，不能把测试账套配置当作正式账套已有配置。
- `303-monthly.json` / `303-annual.json`（code303）：22行月报及本年/上年全年取数，现金范围1001/1002/1012。现金分录的SBxx分类取净额；内部转存SB_INTERNAL不计三类活动；退款冲减原类，处置费用抵减行10，资本化借款利息列17、工程人员工资列4。借贷分类金额、内部转存、期末总账共8项核对。年、月版本同code，不能同时引入同一账套。
- 全部JSON使用实际 `ReportTemplateSchema` 和共享 `balanceFormula`，通过真实router导入、生成、模板导出、xlsx导出；只读模板、整数分、未过账确认、权限和失败后保留上次快照均保留。三表表内、名称及导出均保留未完成/试算标记。
- 测试经core/testkit造合成数据，不依赖本波页面。固定黄金值含结转后本年利润9696分/上年14098分、非损益结转501分保留、按往来分方向余额、两年现金期末466384/274397分，以及显式明细映射32行逐格手算。E2E只经core接口选基线已有小企业科目表、core/testkit造数、报表页真实引入/生成/刷新/下载。

共享契约及仍需的共享改动：

- 正常合入指定共享c9快照（含原a8）、PR95指定快照和指定main，未手改其core/server/shared。统一 `BALANCE` 原7参加可选第8个JSON字符串，由实际 `BalanceFunctionSchema` / `balanceFormula({原七字段, options})` 编码；不另造API。
- `from/to` 用current、yearStart、previousMonth、previousYearStart、previousYearEnd、previousYearSameMonth/previousYear或YYYYMM；opening为from前期初，closing为to期末，发生额为闭区间，ytd按to年度。`closing:excludePnl`仅发生额排真实pnl；余额不排结转。`side:debit/credit`先按末级及groupBy辅助项取正数，再汇总。
- 仍需owner提供公共法定profile持久绑定、generate原子预检、审核失败/错误阻止正式生成及导出、逐现金分录分类完整性及现金范围/启用前项目分配、期限/到期日分析数据、年报期间策略。不得把模块测试调用validator当公共强制门禁，不得用IF除零、缺科目、未知来源或假零替代这些能力。
- 存货所需guard契约（待共享owner实现，当前不新增schema字段/API）：服务端持久绑定账套、制度profile版本、映射及完整科目表指纹/版本；generate在同一事务核对真实科目表、缺角色依据和完整末级覆盖，无绑定、absent重新存在或明细漏覆盖则拒绝。母科目范围合法新增明细后应重新核实并正常生成，不能一概永久禁止新增科目。快照记录本次绑定，export再次核对并拒绝旧无guard快照、失效依据或审核失败。不能仅校验客户端提供的科目表快照。具体字段和失配处理见本PR「需要的共享改动」。
