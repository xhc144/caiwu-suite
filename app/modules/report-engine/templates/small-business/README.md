# 小企业三表（W2-03）

依据 `rules/sources/official/small-appendix.pdf` 第68—85页及编制说明，保留原文项目名；本目录是未完成的取数切片，不是完整法定报表。原版入口为报表管理 `w_bb_main`、模板引入 `w_bb_get`、报表定义 `w_bb_def`、报表生成 `w_bb_proc`、数据导出 `w_bb_saveas`。不读取旧C#或重新解析安装资源。

功能清单：

- `301.json`（code 301）：53项完整行次；28项直接余额、备抵净额及年度期初还原已接真实引擎。清理贷余、税款借余保留负号。其余格明确标记“未实现”，不生成完整合计；年初用期末减本年借方累计加本年贷方累计，既不取本月期初，也不写死1月。
- `302-monthly.json` / `302-annual.json`（code 302）：32项表样；月报为本年累计／本月，年报为本年累计／上年。取数未实现；已有退货、成本冲减及损益结转前后固定账套，手算净利润3297分，验证单边累计和结转后余额均不能替代真实利润。全部金额格保留缺项。
- `303-monthly.json`（code 303）：月报22行接真实现金分录、累计和月初／年初，现金科目范围1001、1002、1012，避免上级／下级重复。按现金分录的SBxx分类作净额，内部转存SB_INTERNAL；退款冲减原项目，处置费用抵减行10，购建借款利息列行17、工程人员工资列行4。8项金额核对包含借贷分类金额、内部转存及总账期末现金。
- `303-annual.json`：本年累计可取数，上年金额未实现。与月报使用同一code，不能同时导入同一账套；需要比较时先复制为其它编码。
- 全部JSON使用实际 `ReportTemplateSchema`、只读模板及白名单公式。可由现有引入、生成、模板导出、xlsx导出流程使用；没有注册新的路由、页面或共享字段。
- 独立测试用core/testkit合成数据，经过真实router导入、生成、导出、权限、未过账确认及失败事务；E2E不依赖凭证录入、审核或结账页面。测试失败不加retry、不删断言。

未完成项：

- 301：应收／预收、预付／应付按往来明细借贷重分类；超过一年预付／预收；一年内到期的资产负债；存货和在产品分析填列、长期债券、长期待摊、递延收益、其它流动／非流动资产负债；中外合作经营已归还投资；实收资本分析；未结转利润与未分配利润；流动／非流动及资产、负债、权益各项完整合计、平衡和存货包含关系审核。

需要的共享改动（仅由唯一owner实施）：

- 现有签名 `BALANCE(account,metric,unit,currency,direction,dimension,item)` 全为字符串，只有生成月。请求独立扩展（建议名 `BALANCEAT`，最终由owner定）：增加 `from`、`to` 两个相对期间字符串，至少支持本年初、当前月、上年初、上年末；不改变原7参含义。上年列需要上年全年发生额，不能拿12月或当月替代。
- 发生额指标需明确支持“排除可识别损益结转的净借方／净贷方”：输入科目、期间范围、已过账口径，输出安全整数分。不能靠摘要、凭证日期、借贷单边或猜测来源识别结转。
- 重分类需先按末级科目及往来辅助项分组，再取借／贷余额，最后汇总；同时需要账龄／到期日与长短期分析输入，年初与期末各自计算，不在报表模板中猜期限。
- 需要 `checks` 的阻止等级及服务端执行：审核失败／错误不能生成正式结果或导出，失败不覆盖上次成功快照。现金流量还需逐现金分录缺分类／无效分类阻止、现金范围／受限资金配置及启用前分类分配。当前schema没有这些字段，本任务没有越界添加。

试用：在小企业科目账套的“报表管理”引入本目录JSON；301可直接试算已接项目。303先建立 `cashflowItems` 列出的16个SBxx项目和SB_INTERNAL，在现金分录上填写；全部存在才可生成，缺科目／项目会报错，不补零。选择期间生成，再导出xlsx核对“口径与审核”；任何核对失败均应停止使用该试算结果。报表名称和表内未完成标记会保留到导出。年、月版本同code需选其一。
