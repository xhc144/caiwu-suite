## P1：有效账套备份/升级在 Windows 文件共享处失败

最小入口：在该提交的 Windows checkout，运行 `dotnet run --project tests/Caiwu.Delivery.Tests/Caiwu.Delivery.Tests.csproj -c Release -- artifacts/delivery-components/current.json`。

实际日志中，`verified upgrade backups preserve independent SQLite balances`、WAL备份、正常分阶段迁移等抛 `System.IO.IOException: ... being used by another process`。首个共同栈为 `PayloadManifest.Hash -> File.OpenRead -> UpgradeSafety.Prepare:70`：`completedBackup` 的 SQLite store 仍在 using 作用域内，同时用仅共享读取的 File.OpenRead 取hash。`BookOperations.InspectWritableCopy:101` 也出现文件共享错误；该路径需另查调用者持有的写连接，不能仅以方法内部的 using 已退出认定所有句柄均释放。

有些身份/版本/trigger迁移反例因此尚未进入迁移回调。必须先修 Windows 句柄/共享方式，再定点重跑这些反例；失败点并不证明相应防护已失效。未擅改 Delivery 生产模块。

## P2：独立 App gate 夹具未到校验点

`dual-windows-results.json` 的 App gate 场景在注入trigger后 `File.ReadAllBytes` 即遭文件共享失败。注入使用默认连接池；本地后续仅将此合成注入连接改为 `Pooling=false`。这个改动尚未 Windows 复跑，不能改写本次原始 FAIL。
