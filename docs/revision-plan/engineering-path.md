# 原软件升级：工程路径与开工门槛

核查日期：2026-10-25。仓库：私有 `xhc144/caiwu-suite`；证据基线：`main@3b0c59b02d8941c32ac176309555c03c94bb4213`。本轮仅新增本说明，不实现产品功能。

## 1. 当前结论

**目标是原软件升级：保留原功能、账套、菜单／窗口／按钮的相对布局及操作习惯，现代化视觉，并逐项修正确实难用的局部。现有 0.1.0.4 独立 WPF 软件不作为目标基线。**

当前能确认的是：

1. **本次可读取材料中，没有已经验证可编译的原 PowerBuilder 工程。** 固定提交的完整 Git 文件树没有 `.pbl`、`.pbt`、`.pbw`、`.pbr` 或 `.sra/.srw/.sru/.srm/.srd/.srf/.srs/.srp` 等 PB 源文件。现存产品项目为 C#/.NET/WPF 与 SQLite；PB 工具项目也是 C# 编写的分析工具。不能把它们称为原工程。
2. **Claude 的原版静态分析已经存在，而且可直接用于升级规划。** [原版分析总说明](../original-analysis/README.md)、各产品窗口／菜单资料和机器可读 JSON 已提供大量原程序结构；本轮不重做安装包解析。分析完成其声明的静态工作，与恢复可编译工程是两件事。
3. **仓库中的反编译导出器不是源码工程恢复器或 PB 编译器。** 它输出描述、文本和二进制片段，有局部解码状态；当前没有 PB 导入、全量编译或原版运行对照的证明。
4. **缺可编译原工程，不等于不能保留原软件的使用方式。** 已有菜单树、PBU 控件位置、窗口祖先、快捷键和事件摘要，为保留布局与操作路径提供了具体依据。但“全部行为和原账套兼容”仍须经过源码／恢复完整性及运行回归验证，不能仅凭描述保证。
5. **优先核实原 PB 源工程，暂不切换实现路线。** 若现存材料只有编译 EXE/PBD，先判断能否恢复成可编译 PB 工程；若最终只能行为保持式重建，应把它作为改变底层实现的独立方案交用户决定。本说明没有采用重建，也没有批准继续扩展旧 WPF 预览。

结论的范围是本提交、远端可见分支／Release 元数据和本环境。它不证明用户、原作者或其他已授权工作区绝对没有源码；也不假设我们已经拥有这些未见材料、凭据或工具许可。

## 3. 原程序结构及依赖：已知事实与待核项

### 3.1 不能只改一个主 EXE

按[原版分析](../original-analysis/README.md)及各产品 README：

| 产品／入口 | 原结构 | 不能丢失的关联 |
|---|---|---|
| [轻松账务](../original-analysis/products/qingsong/main/README.md) `run_zw8.exe` | 主 EXE，加按顺序加载的 `rhzw8_8`、`rhzw8_1…7/9`、`rhzw_ROOT` 等 PBD | 账务、账簿、报表、分析、合同、系统与账套功能 |
| [民非主程序](../original-analysis/products/minfeiqi/main/README.md) `rhzw8_mfq.exe` | 账务基线另含 `rhzw8_zc1`、`rhzw8_gz1` | 工资、固定资产，以及民非制度科目和报表模板 |
| [成本主程序](../original-analysis/products/chengben/main/README.md) `rhzw8_cb.exe` | 再含 `rhzw8_cb1/cb2` | 仓库、出入库、库存、成本核算、相关凭证和报表 |
| [出纳](../original-analysis/products/qingsong/cn/README.md) `rhzw9_cn0.exe` | 独立进程，`rhzw9_cn0/1/2`、`rhzw9_root` | 三套共有；不能只保留主程序内的一个入口 |
| [发票](../original-analysis/products/qingsong/fp/README.md) `rhzw9_fp0.exe` | 独立进程，`rhzw9_g/g1` 并加载部分账务库 | 轻松／成本共有；成本与轻松的程序上下文仍分别核验 |

`windows.json` 中轻松 `w_frame` 位于 `rhzw_ROOT.pbd`，`windowtype=mdihelp!`、主菜单 `m_frame_zw`；`w_main1` 位于主 EXE。凭证录入 `w_pz_pzedit` 位于 `rhzw8_1.pbd`，继承 `wroot_share`，使用 `m_work_pz_pzedit` 和主从 DataWindow。这是原有 MDI、祖先窗口、菜单与用户对象共同构成的 UI，不是可通过替换一个首页完整升级的独立页面集合。

主框架／子窗口切换菜单、多个 sheet、模块切换登录、独立出纳／发票进程，都属于需要保留和回归的使用方式。PBD 名称不是独立业务模块的充分证据，也不能随意改库搜索顺序。

### 3.2 依赖不能从文件名推定可用

- **PB 运行时事实：** [PE 元数据](../reference-static/program-types.json)中的三个主程序为 x86 PE32、CLR 目录为 0，直接导入 `KERNEL32.dll` 与 `PBVM90.dll`。支持“依赖 PB9 运行时”，不证明每个对象编译方式或 PB9 开发器／补丁版本。包内同时有 PB6、PB9 组件；不能只留下其中一套就声称所有辅助程序可用。
- **数据库事实：** 清单有 `rhsj/Rhzw01.db`，轻松／成本同哈希、民非不同；同时包含 SQL Anywhere 8/9 相关引擎、驱动和工具。结构报告将其归于 SQL Anywhere 系列，但**实际账套数据库文件版本、活动引擎、连接接口、DSN／连接参数、日志和加密状态仍未在本轮核验**。`asa8` 目录名不能证明只用 8；附带 `pbodb90`／`pbmss90` 也不能证明业务实际选择 ODBC／SQL Server。
- **资源事实：** 清单有 `Rhzw8.ini`、`autoupdate.ini`、`Bb000.vts`、取数 `.xlt`、`HttpDownX.ocx`、`TTF16.ocx`、帮助和图片；[导航资料](../original-analysis/products/qingsong/main/navigation.md)还记录图片资源名。它们的调用、注册、相对路径和实际加载须核实；不要把 OCX 出现在包里就写成业务必需或已成功注册。
- **产品差异事实：** [静态模块比较](../reference-ui/static-program/README.md)显示三包同名账务 PBD 可能同大小而不同哈希；出纳部分库同哈希。只能按内容哈希去重存档，不能因此互换三套账务库。PE 导入名级边也不是已验证的 Windows 加载绑定。
- **工具资源边界：** `tools/pbdviewer-export/resoures/*.bin` 由 [PbFile](../../tools/pbdviewer-export/Uitils/PbClass/PbFile.cs)按版本作为系统类型资料读取；不能把该目录当成已取得的原软件图标、报表或源库。

`reference-ui/static-program` 保留的是较早一批元数据研究状态；其中“尚未解码”的旧描述不应推翻后续 `original-analysis` 已交付的菜单／窗口分析。反过来，后续静态说明也不能自动补出尚未交付的可编译工程或实机证据。

## 4. 路线选择及最小缺项

### A. 在原 PB 源工程上直接升级 UI（优先核实）

含义：继续使用原应用对象、窗口／菜单／DataWindow／用户对象及业务脚本、库结构和数据访问方式，在其源工程中修改视觉和明确批准的局部交互，编译成新版本。

**现在的状态：尚不能开工修改原源工程，原因是可读取的原源码与构建环境未到位；没有证据证明这条路线永久不可行。**

最小需要补齐并验证：

1. 对应已分析版本的**完整源对象**：可含源码的开发 PBL，或完整、可导入的 SR* 导出；必须包含应用对象、被引用的祖先／用户对象、菜单、函数、DataWindow 和共享源库。只有运行用 PBD、EXE、结构 JSON 或若干事件文本不够。
2. 可确定的 Target、入口和库顺序／编译配置。现成 PBW/PBT 最方便，但它们本身缺失不必判死刑：若源对象和原构建设置完整，可重建工作区／Target 后验证。反之，只有 PBW/PBT 而没有源库同样无用。
3. 与原版匹配、可合法使用的 PB 开发／编译工具及补丁、Windows 构建和运行环境；完整的资源引用、外部声明／组件、数据库驱动及配置。不能把包内 PBVM 当作编译器，不购买或假定许可。
4. 能启动的隔离原版基准、已授权的非生产账套副本／合成夹具，以及可验证的备份恢复过程。无需用户电脑在线；本轮不操作用户电脑。

开工判据：先在隔离目录完成一次**未改 UI 的全量 regenerate／构建**，所有源库及依赖可解析，生成版本可以在受控 Windows 环境按原路径打开和读写测试账套。二进制不要求字节一致，但关键流程、查询结果、持久化及打印输出应对照一致。随后只选一个已知小窗口做视觉样片，验证可回滚，再扩展。

### A2. 恢复可编译 PB 工程后继续升级（条件路线）

若没有开发源工程，已有反编译结果可能帮助恢复 PB 源对象，但**目前没有证明恢复已完成，也没有证明不可能恢复**。这是源码恢复工程，不能把现有导出器改个文件后缀当成已经成功。

需先检查已有报告而非重跑整包：每个程序的请求／缺失库、对象选择顺序、逐函数 `status`／诊断、祖先和外部声明、DataWindow 可导入定义、资源引用；对动态创建、消息事件绑定、嵌入式 SQL、游标、事务和计算表达式逐项验证。特别注意导出器顶层对象成功计数与函数局部失败不是同一粒度。

只有恢复对象可导入 PB、全量编译，并完成未修改版本的行为对照，才可转入 A 的 UI 升级过程。恢复时重写缺失业务算法属于额外实现工作，必须单独评审，不能暗中补一个简化版本。读取或分享新的完整反编译输出亦不在本轮授权中。

### B. 行为保持式重建（仅解释，不采用）

含义：使用另一套源代码重新实现同一套窗口、菜单、数据操作和业务行为。它可以被严格要求保留原软件的全部入口、布局和习惯，**缺原源工程不构成放弃这些要求的理由**；但它仍更换了实现，不能称为“在原 PB 工程上换皮”。

它与 A 的关键差别是：原业务代码／DataWindow 机制／事务和事件语义不再天然延续，必须逐项重现和证明。若再把数据库改成 SQLite，还增加了完整数据迁移、读回、跨版本兼容及回滚义务。若考虑继续连接原数据库，也须验证原模式、驱动、锁、事务及旧程序互操作，不能假定“同一数据库”就等价。

**现有 WPF 0.1.0.4 的功能子集与 SQLite `.caiwu` 账套不满足 B 的完整兼容承诺。** 不以继续给它加几个功能替代用户要求。只有在原工程／恢复路线的材料核查完成后，将具体证据、无法补齐项、完整范围和成本提交用户明确选择，才能启动 B；此处不推荐简化替代。

二进制补丁、注入皮肤、外部套壳或并列放一个新首页，当前都没有足以证明完整保留行为的可行性证据；本轮未选择、未尝试这些方案。

## 5. 保留原数据的技术门槛

**“保留账套”是必达要求，不能降成将来可选导入。** UI 升级优先维持原数据库引擎、模式和访问路径；引擎升级、模式迁移或换存储应作为独立变更评审，不与第一轮视觉升级捆绑。

| 门槛 | 必须具备的证据 |
|---|---|
| 识别账套实体 | 核实真实版本／引擎／连接参数、数据库与事务日志、目录结构、账套登记和关联文件；[套账窗口](../original-analysis/products/qingsong/main/windows/tzjl.md)引用 `dba.xttz`，不能先假定“一账套就是一个独立 DB 文件” |
| 取得一致基线 | 使用已授权测试副本；通过匹配引擎的备份／恢复建立一致快照，记录来源与文件哈希；运行中的 DB 不能用普通文件复制冒充一致备份。凭据不进入文档／Git |
| 证明数据完整 | 在副本对比所有适用表／变体、主外键与索引、触发器／过程／默认值（若存在）、记录数、精确金额和数量、中文编码、空值／空串、日期、外币精度、主键和关联，不只对比余额合计 |
