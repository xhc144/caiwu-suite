## 之前为什么跑偏

1. **没有共同地基就开始并行**：每个对话各自发明一套数据模型和目录结构，最后合不到一起。
2. **WPF 在 Codex 云端跑不起来**：云端是 Linux，GPT 没法真正运行和测试界面，于是大量精力花在 Windows CI、截图证据、交付门禁、SHA 清单上。
3. **任务写得太虚**：只写"参考文档实现"，没有落到原版的具体窗口和规则上。

新方案对应解决这三点：
1. 地基已经做好，并行任务各自只改自己的目录，边界检查自动拦截越界。
2. TypeScript 全栈，在 Linux 上能完整跑、完整测：`cd app && pnpm check` 一条命令。
3. 每个任务都列出原版窗口名和规则清单；AGENTS.md 明确禁止写证据文档。

## 地基里已经有什么（Wave 0，已完成）

- **工作区**：pnpm workspace，TypeScript 6 strict，ESLint，Prettier，以及架构边界检查（模块之间不许互相 import，前端不许引服务端代码）。
- **核心数据模型**：账套、期间、科目（级次可配置、辅助核算、外币、数量、现金流量标志）、五种辅助核算维度、凭证与分录、期初余额、用户与权限、操作日志。
- **核心服务**：
  - 凭证：保存校验、自动编号、乐观锁、来源单据保护、统一的状态变更入口
  - 账表：余额查询（辅助核算展开、外币、数量、本年累计、年结前可跨年）、分录明细、试算平衡
- **模块机制**：在 `modules/<id>/` 建目录就能被自动发现，菜单、接口、表、页面都自动接上，不用改任何共享文件。写操作必须声明权限点，表名必须带模块前缀，启动时都会检查。
- **前端壳**：账套选择、新建账套、登录、左侧导航（按产品形态和权限过滤）、多标签页（切走再切回不丢状态）、快捷键、带操作按钮的统一错误提示。
- **通用组件**：金额输入与显示、科目选择（编码、名称、拼音首字母）、辅助项选择、期间选择、数据表格（可拖列宽并记住、导出 Excel、虚拟滚动）、筛选栏、危险操作确认框。
- **示范模块** `modules/example`：录入记账单，一键生成凭证。完整演示了表、权限、业务规则、事务、页面、单测和 E2E。
- **测试**：71 个单测（含 fast-check 随机凭证的试算平衡不变量）和 5 个 E2E，全绿。
- **桌面壳**：Electron 主进程和 preload，本地服务能打包运行；安装包配置是初版。
- **CI 与 Codex 配置**：`.github/workflows/app-ci.yml`，以及 `app/CODEX_SETUP.md`（Codex 环境的 setup script）。

## 操作步骤

1. **合并地基**：把地基分支（`claude/elegant-sagan-91n3gs`）合并到 main。Codex 任务从 main 起步，地基不在 main 上，后面的任务就看不到。
2. **配置 Codex 环境**：按 `app/CODEX_SETUP.md` 设置环境的 setup script。不设的话，任务装不了依赖，也跑不了 E2E。
3. **补充难用点**：打开 `orchestrator-prompt.md`，在「要改掉的难用点」第 15 条写上你自己想改的。
4. **交给总控**：把 `orchestrator-prompt.md` 全文贴给 GPT 总控，它会输出 Wave 1 的 21 个任务提示词。
5. **同时开 21 个任务**：attempts 按总控给的建议开，2 到 4 个。
6. **合并**：每个任务做完就建 PR。CI 是绿的，并且只改了它自己的目录，就直接合并，先后顺序无所谓。遇到锁文件冲突，或者 PR 改了别的目录，就把 PR 贴给总控处理。
7. **进入 Wave 2**：全部合并后，告诉总控"Wave 1 全部合并"，它会输出 Wave 2 的任务（逐模块对照原版补漏、成本核算、三套法定报表）。
8. **实机试用**：M21 合并后，GitHub Actions 会生成 Windows 安装包。自己装上试用，把发现的问题贴给总控，这些问题进入 Wave 3。

## 额度怎么花最值

- **attempts**：同一个任务跑多个版本再挑最好的。凭证录入、报表引擎这类大任务开 4 个。
- **Wave 2 逐模块补漏**：每个模块一个任务，对照原版逐个窗口、逐条规则核对，可以并行很多路。
