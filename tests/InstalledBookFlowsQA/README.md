Independent external UIA controller and workflow; product is always the NSIS-installed self-contained `Caiwu.Desktop.exe`, started by installed `Caiwu.Delivery.exe launch-managed`. Never executes a source project as the product. Uses the existing hash-pinned preparation/NSIS pipeline and synthetic operator initialization APIs. Existing InstalledDesktop controller and all production code remain untouched.

Baseline: `dece298946d03ad88c5031eb02dab8f87c330046`; branch begins at `2707a72ffe1b73fed715517802e6ad62e48fe611`, whose intervening changes are evidence/documents only. Workflow asserts unchanged production and existing controller against baseline. `sourceCommit` in every new report is the actual new clean checkout/payload SHA, not the older baseline SHA.

Cases exercise normal login/create/save/distinct-actor review/post, both voucher-copy cancellation stages, actual copied-draft save using native repeated mouse input, exact original voucher semantic preservation, duplicate voucher-number refusal, summary category/text add/save/cancel/reopen, actual book-copy full execute/register with a different BookId and persisted source audit, stale preview approval rejection, cancelled preview, duplicate destination rejection, complete backup/trusted receipt restore preserving BookId, and distinct physical instance summary directories despite equal BookId. The source SQLite is captured read-only for observations. Two real install/data OS leases are checked while App runs; no lock files or trust receipts are manufactured or weakened.

A second installed self-contained helper process inspects all three ledgers after App exit, asserting identities, exact semantic equality of source and restore, two vouchers/one posted and 123.45 bank balance. A fresh managed-data session checks physical identities and attachment inventory. Native uninstall retention compares all synthetic data hashes. Artifacts contain only explicitly selected reports/logs/native full-screen PNGs and payload hash metadata; no installer, payload binary, ledger, identity store, original resources, or derived reference materials are uploaded.

Current limitations are intentionally failing or not run, never green entrypoint claims:

- Installed voucher editor currently has no summary choose/refill control. `summary-refill` records actual native screenshot and full button inventory, then fails with a minimal reproduction; it does not paste text through automation and call that refill.
- `stale-source-revision` is not run. No supported normal installed UI action can mutate the source while its owned modal editor remains open. Manufacturing that condition by writing behind the App-owned managed data lease or changing credentials/permissions is outside this fixture. Stale preview approval after input change is covered separately and is not equivalent to a stale source/session test.

Workflow: `.github/workflows/windows-installed-bookflows-qa.yml`. A failed case is captured and independent later cases continue. Top-level preparation failure records any completed checks. The workflow fails when any requested case fails or is not run. Read `runtime/installed-bookflows.json` and `installation-and-independent-readback.json`; compilation, window opening, and fixture startup never count as business success.
