# 可编辑成本工作表与待审核结转建议

本轮复用 `codex/costing` 的库存/生产领域及 `CostMath.Allocate`；没有重写库存来源核算，没有改 Core、Contracts、SQLite、Desktop 或 solution。旧 `ProductionCosting` 继续用于真实领料事件归集。本工作表是另外一个明确的入口：**输入已由业务确认、按成本对象归属的新增材料金额，以及材料/人工/制造费用池和基础，计算并导出待审核建议**。不得把同一材料同时作为直接材料、共用材料池或承接成本重复输入。

新软件计算方式为 `worksheet-whole-stage-largest-remainder-rmb-v1`，不是对原软件算法或默认值的复刻声明。原安装器、窗口、SQL及对象目录均未读取、执行或新增上传。

## 可操作闭环

独立页面 `Caiwu.Costing.Wpf.CostWorksheetPage` 提供日期/制表人/来源依据，三个输入表（阶段费用池、对象与基础、阶段承接），以及计算明细、精确分配审计明细、待审核凭证建议。

1. 按加工顺序增加阶段，为每阶段明确选择材料、人工和制造费用各自的基础：产量、人工工时或机器工时。产量基础需要审核人确认可比的计量口径；本模块不做单位换算。
2. 增加成本对象，填写新增直接材料、完工产量和工时。新行数值留空，须逐项明确输入；未知金额必须补齐来源，不能以0代替未知；0表示确认零成本。
3. 可选：增加整批承接关系，将更早阶段某对象的全部材料、人工和制造费用转至本阶段一个对象。来源只允许使用一次；不支持拆分、损耗、在产品、循环或未来阶段引用。未被承接的对象视为终端整批完工。
4. 点击“计算 / 复算”。改动任何输入或增删行会立即清除旧明细和旧建议，导出前必须复算。输入错误会保留在单元格，并显示明确错误；不把无效数值转换成0。
5. 导出 JSON 留存完整输入、计算方式、金额/尾差明细、来源引用、账套/工作表标识、SHA256输入指纹及待审核建议；也可导出 CSV供检查。打开 JSON 时核对当前账套、重新计算并逐项核对完整报告，包括显示单位成本。SHA256和复算检查用于一致性，**不是数字签名、身份认证或防恶意篡改证明**。

内置“载入合成样例”是显式操作，不读账套、不读原软件。默认示例为两阶段250元；将第一阶段人工80改为84，复算为254元。

## 精度与边界

- 人民币金额最多2位有效小数，总外部投入及每对象成本不超过 `92233720368547758.07` 元；数量和工时最多4位，单项不超过十亿。数量必须正数，工时可为0。金额、工时和数量均不允许负数，冲回/更正须另走主系统已审定流程。
- 单位成本显示6位；结转始终使用完整对象总成本，不能用显示单位成本乘回产量。
- 三个费用池共用已有整数分/BigInteger最大余数算法：向下截至分，余分按精确余数降序分配，同余数按成本对象 `StringComparer.Ordinal` 升序分配。非零池配零总基础会拒绝；零池配零基础得到0。
- 每笔分配保留整数分×整数权重的精确分子、总整数权重分母、截整金额、尾差补分及最终金额。权重放大10000倍。零池/零基础的分子分母均0，结果直接0，不执行除法。
- 对象及承接输入会规范排序，因此单纯调整它们的行顺序不会改变金额、指纹或导出。阶段顺序保留，因为它定义依赖关系。
- 同阶段对象标识及阶段标识不得重复；不同阶段可以重用对象标识。最多32阶段、合计1000对象和1000承接关系。JSON导入/导出上限4MiB；超过时明确拒绝并要求拆分，不保存无法重新打开的文件。

每阶段 `对象成本合计 = 本阶段新增投入 + 承接成本`；全表 `终端完工成本合计 = 所有阶段新增投入合计`。承接额不再算新增投入。

## 公开 API 与主界面最小接入

核心项目保持 `net10.0`、无额外第三方包；WPF在子项目 `Wpf/Caiwu.Costing.Wpf.csproj`（`net10.0-windows`）。主集成可单独加入两个项目/项目引用，不需要改共享契约。

```csharp
// 纯应用服务，可由桌面、批处理或测试调用。
var calculation = new CostWorksheetService().Calculate(worksheet);
var json = CostWorksheetExport.ToJson(calculation.Input);
var reopened = CostWorksheetExport.FromJson(json, expectedBookId);
CostWorksheetExport.SaveNewJson(newJsonPath, reopened.Input);
CostWorksheetExport.SaveNewCsv(newCsvPath, reopened.Input);

// 主界面只需在本来允许操作的账套/日期上下文中创建页面。
var page = new Caiwu.Costing.Wpf.CostWorksheetPage(currentBookId, selectedDate);
// 宿主将 page 放进现有内容区或窗口；切换账套时重建页面。
// 点击页面的计算按钮后，可读取 page.Editor.Result / CanExport。
```

`CostWorksheet`/`CostStageInput`/`CostObjectInput`/`StageCarryInput` 及计算结果定义在 `WorksheetModels.cs`。返回列表冻结，调用方修改原数组不能改写已算结果。`CostWorksheetEditor` 是与WPF共用的可测编辑状态； `Load(input)` 后须 `Calculate()`，不能直接导出未复算输入。

**本轮不自动保存或记账。** 建议使用现有 `CostAccountRole`，未填任何猜测科目编号。宿主若要采纳建议，仍须核对制度包/当前账套/期间、真实业务来源与已有总账分录、活动末级科目映射、制单审核身份、以及最新账套revision，再通过既有Core保存草稿。不得绕过现有审核与记账保护。

建议唯一键在相同工作表和同类业务间稳定。适配器应以账套ID、工作表ID、输入指纹和建议唯一键核对防重；同工作表ID的新指纹不能覆盖已经审核/记账的版本。文件本身不能保证多进程幂等或账套事务安全。

## 文件与数据保护

导出先完成全部验证/序列化，再写同目录的新临时文件，使用不覆盖的移动产生目标文件；失败清理本次临时文件。只接受 `.json`/`.csv`，拒绝覆盖任何已有文件，包括选择了已有导出文件的情况；也不会写 `.caiwu`/SQLite。CSV文本字段加引号并防公式前缀。导入只读且限制大小，不会修改来源文件。未实现账套数据库迁移、安装/更新或删除逻辑；现有账套保护不受本模块影响。

## 规则与适用性

已只读核对远端 `codex/accounting-rules` 的 `rules/packages/enterprise.json`、`rules/enterprise/README.md`、`rules/sources.json`。现有企业制度包明确是工程参考，数字编码有未核项，`isVerifiedForProduction=false`；成本角色不能据此硬映射为正式已核科目。

2026-10-25通过财政部官网核对财会〔2013〕17号发布通知：其规定的实施范围为除金融保险业外的大中型企业，其他企业可执行。[财政部官方通知](https://www.mof.gov.cn/gkml/caizhengwengao/wg2013/wg201309/201403/t20140319_1056828.htm)。本轮核验通知范围，未完成所有正文条款/后续行业制度的适用性审阅；最大余数、整批承接及上面的功能限制是本软件的明确支持方式，不声称是法律要求或原版行为。财政部另有石油石化行业制度，说明行业规则需要分别核验，[官方通知](https://m.mof.gov.cn/zcfb/201412/t20141229_1173216.htm)。

本工作表仅覆盖无在产品、无损耗、整批完工及整批阶段转移的简单制造成本计算，不覆盖金融保险、农业/建筑/石油石化等专项行业、联副产品、复杂分步、约当产量、税务、减值或完整ERP，不构成完整成本核算合规认证。
